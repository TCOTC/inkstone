# inkstone 设计

> 本文只写两件事：**有哪些功能**（一句一条）、**架构上长期不变的约束**。
> 具体交互、字段、命名、文案一律以代码为唯一真相源，本文不复述。
> 工程流程（怎么建、怎么测、代码放哪儿）见 `AGENTS.md`。

## 一、这是什么

本地优先、无账号的网页划线扩展。划线存在 `chrome.storage.local`，**不经过任何自建服务**。

唯一的外连有两处，且都可以不用：划词翻译 / 解释（用户自备 DeepSeek Key，请求从 service worker
发出）、跨设备同步（走 Chrome 账号同步，不经过第三方）。两处都不开时，扩展是纯离线的。

真正要保证的是**落不回原处的划线可被发现**：进「未定位」清单，不能静默丢弃。

## 二、功能

| 能力 | 一句话 |
| --- | --- |
| 划新划线 | 选中网页文字 → 工具条 → 高亮 |
| 回放 | 正文有改动时按「近似」落点并标注 |
| 查看 / 删除 | 点划线弹出工具条，可删除；原文与时间在本页列表里看 |
| 翻译 / 解释 | 对选中文字或整条划线发 DeepSeek 请求，流式显示，可按需联网搜索 |
| 复制 | 复制选中文字或整条划线的原文 |
| 本页列表 | 左键点工具栏图标，右侧滑出本页全部划线，含「未定位」分区 |
| 右侧标记点 | 页面右缘一列短横线，按位置标出全部划线 |
| 我的划线 | 跨页浏览、搜索、跳回原网页定位 |
| 偏好设置 | 画笔样式、启用开关、AI 配置、同步开关、备份与清空 |
| 跨设备同步 | 设置始终镜像；划线数据按开关镜像；两侧新增合并、删除传播 |

界面形态、按钮顺序、文案、错误提示——全部看代码。

## 三、明确不做

自己的账号与服务端、划线级标签 / 批注 / 文件夹、公式与图片划线、全文剪藏、写回任何第三方服务、
Chrome 以外的浏览器。

**也不索引 Shadow DOM 与 iframe**：坐标系从 `document.body` 起按 light DOM 遍历。
落在这些区域的划线只会进「未定位」清单——这是已知边界，不是 bug（支持它要另一套渲染层，
成本远高于收益）。

## 四、数据

### 4.1 存储形态

`chrome.storage.local`，**一页一个键**：`p:` + `pageKey(url)`，划线内嵌在页行里。

选 storage 而不是 IndexedDB 是架构决定：这套数据就是「按页面取一个 JSON」，没有二级索引、
没有跨表事务、没有容量压力；而 storage 对 content script 直接可见，于是
「content → background → 数据层」这一整层代理与消息协议都不必存在。

三条长期约束：

- 存储键名压到 1~2 个字母（省掉的体积占总量可观），映射**只准**出现在 `shared/rowCodec.ts`，
  其余代码只用 `PageRecord` / `HighlightRecord`。
- 只有「运行时有人读」的字段才留在数据模型里。加字段前先回答它支撑哪个功能；派生的值现算。
- 同一页的写操作走页级锁（4.6）。

### 4.2 页面键

| 函数 | 用途 | 做什么 |
| --- | --- | --- |
| `pageKey(url)` | 存储键 | `new URL()` 那一套不改变语义的规范化 + 清 fragment |
| `looseKey(url)` | 回退匹配 | `pageKey` 再去掉追踪参数 |

`pageKey` **刻意不做**任何会改变语义的合并：删 / 排序 query、去尾斜杠、强制 https、删 `www.`、
路径转小写、`index.html` → `/`。这些都要「先观察到重定向」才成立，离线做不到。

查找两级：精确键 → 按 `looseKey` 比**键名**。第二级只调 `getKeys()` 不读值——键就是
`p:` + `pageKey(行里的 url)`，所以不必把整库反序列化一遍。只在**唯一命中**时采用，
多个候选宁可当作「本页没有划线」，猜错会把别人的划线画到这个页面上。
两级都只读，写入永远写回精确键。

### 4.3 数据模型

`PageRecord`：url / title / createdAtSec / highlights。url 与存储键同源（解码时统一归一到 `pageKey`）。
`HighlightRecord`：id（**页内序号**，导入时按页重新编号）/ text / prev / next / createdAtSec。
时间字段一律带单位：行里的 `createdAtSec` 是秒，墓碑与 `unresolved.failedAt` 是毫秒。

- `prev` / `next` 存的是**原始空白**，比对前才归一。它们既是降级链条的一环，也是同一句多次出现时
  唯一的消歧手段。
- 站点名、无 fragment 的 URL 这类派生值不存。
- **不存「谁创建的」**：划线的同一性只看内容签名（text + prev + next 归一），合并与导入
  都用它判断，所以来源字段不参与任何行为，只会变成一份会失同步的副本。
- **不认识的存储字段原样保留**（`extra`）：解码时收出来，编码时 spread 回去，合并与导入时取并集。
  于是一个旧版本既不会把新版本写的字段抹掉，也不会因为「不认识」而报错——回退再装回新版本，
  数据还是完整的。代价：旧版本改不了它（它本就不懂），也不该在任何判断里读它。

### 4.4 空页不落地

一页的划线数为 0 时整页记录一起删掉。页行只承载「这页有哪些划线」，留着只会在「我的划线」里
挂一条空条目、白占同步端项数。四个入口同一条规则：删最后一条 / 读列表 / 导入 / 同步。
同步侧是**删键而不是写空页行**——空行会被另一台设备当成数据存下来。

### 4.5 备份

一个 JSON：`{format, exportedAt, settings, pages}`，`pages` 与存储行**完全同形**，
所以「导出 → 手改 → 导入」不需要第三套格式。`format` 用于选错文件时给准确提示。

**刻意没有版本号。** 版本号能做的唯一事情是「拒绝」，而拒绝在这里等于「用户的备份变成一堆废铁」；
真正要保护的兼容性靠两条纪律做到：

1. **字段只增不改**——新增字段旧版本靠 `extra` 原样带回（见 4.3），不丢；只有**改变已有字段的
   含义或类型**才是不兼容的，那种改动本来就不该发生在已发布的数据上。
2. **解析不猜**——缺字段按默认值补齐，不认识的字段保留但从不解读。宁可当没看见，也不硬猜。

导入按内容签名与同页旧数据做**并集**，与跨设备合并同一套判等：备份里的线是权威（覆盖同签名的
旧版本），本机独有的线保留——否则「导出 → 继续划几条 → 导入旧备份」会把这段时间的划线全丢掉。
同一条线在两边的未知字段取并集（本机优先），所以用旧版本导入一份旧备份也不会把新字段抹掉。
保留的线接在导入数据的最大序号之后**重新编号**，不重编会和本地线撞号，之后按 id 删除会一次删两条。
代价是导入不再能用来「瘦身」：想删掉整页请走「清空数据」或直接删划线。`unresolved` 是派生数据，
不进备份。

### 4.6 写互斥

storage 的 `get` 与 `set` 之间没有事务，「读 → 改 → 写」必须自己串行。两级：

| 级别 | 机制 | 解决什么 |
| --- | --- | --- |
| 同一 JS 上下文 | 按锁身份排 Promise 链 | 连点两次、划词的同时点删除 |
| 跨标签页 | storage 里的租约锁（带 TTL） | 同一页开在两个标签页时互相覆盖 |

锁身份用 **`looseKey` 而不是存储键**：同一条记录可能被多个 URL 通过回退匹配指向
（带追踪参数的分享链接、主机大小写），按存储键抢锁就是各抢一把、等于没锁。`looseKey`
与回退匹配是同一套规则，所以「能找到同一条记录的两个 URL 必然落到同一把锁上」；
它比存储键粗，只会多串行、不会少串行。

抢锁是「检查 → 写入 → 回读确认」（storage 没有 CAS，只能靠回读把窗口压到一次往返），
有超时上限，超时就照常写——宁可极小概率互相覆盖，也不要让划词卡住。批量导入按锁身份
排序后逐个抢，避免两个并发导入以相反顺序互相等死。

### 4.7 跨设备同步

`storage.local` 永远是权威，`storage.sync` 只是通道。Chrome **不会**替扩展做 local → sync 的
搬运，所以「同步」必然包含一步主动写入——`Settings.syncHighlights` 的含义就是「要不要把划线数据放进
那个会被 Chrome 搬走的区」，不是「开启 Chrome 的同步」。

| 内容 | 默认 | 为什么 |
| --- | --- | --- |
| 设置（画笔、启用、同步开关） | **始终**镜像 | 开关本身就在设置里；否则「打开同步」得在每台设备上各做一遍 |
| API Key（密文 + 包装密钥） | **始终**镜像 | 它是偏好设置的一部分，新装的设备靠这一步才不用重填（见 9.5） |
| 划线数据（页行） | 可选，默认关 | 页面 URL 与划线原文不该在用户不知情时上云 |

五条长期约束：

- **判等用内容签名，不用 `id`。** 签名是 `text` + `prev` + `next` 归一后的哈希；`id` 是页内序号，
  两台设备各自从 1 数，同号必然撞车。本机行原样保留，远端多出来的接在后面，合并结果与远端
  不同才推回；合并幂等，所以会自然收敛，不需要回环标记。
- **删除靠墓碑。** 只做并集的话，A 删掉的线会被 B 的旧副本复活。墓碑只用于**合并远端数据**，
  本机读页面从不看它——否则「删掉 → 重新导入备份」会被挡住。
- **合并后 0 条就两侧都删键**，本地没有该页时也要过一遍墓碑，否则删光后下一次拉取会原样长回来。
- **配额按 UTF-8 字节量**（中文一字 3 字节）：单页超阈值就跳过并计入报告，不拆块；总量 /
  项数满就停；批量 `set` 以省写操作次数；内容没变就跳过。
- **全量拉取只在 background。** content script 每个页面都跑，让它拉全库等于每开一个网页
  就读一遍同步端。

`storage.sync` 的**设备间传输由 Chrome 负责**，所以界面上没有「拉取」按钮。反过来：
扩展**无法查询**用户是否登录 Chrome、是否勾选「扩展程序」同步（没有这种 API）；
同步被关掉时 `storage.sync` 退化成只在本机、写入照旧成功。所以文案只能说
「已写入同步区」，任何「已同步到其它设备」的断言都是猜的。

关掉开关 = 不再读写云端的划线数据，**云端副本不删**（别的设备可能还在用）。
因此「清除云端数据」是一个独立入口，且不看开关——它的目标场景正是「我已经不用了，
把数据收回来」。同理，副作用要说清：另一台设备仍开着同步时，它下次写某页会把那页写回来。

「清空数据」是另一回事：它连同步端的页行一起清。只清本机的话，下一次启动的全量拉取会把
整库原样搬回来，用户看到的是「清空又长回来」。

**`storage.sync` 不是备份。** 卸载扩展时 Chrome 会一起删掉它在 `local` 与 `sync` 里的数据；
换路径加载的开发版还会换成另一个扩展 ID（见 `identity.md`），也是从零开始。
扩展没有任何在卸载时保存数据的入口（service worker 先被终止，`setUninstallURL` 只来得及
打开一个外部网页）。所以「数据能跨过卸载」的唯一载体是用户**导出的备份文件**——
界面必须把这件事说清，不能让人把同步开关当成云备份。

`unresolved`、墓碑这类派生或辅助数据不参与页行的合并语义（各自单键管理）。

## 五、定位

**坐标系**：把正文文本节点按文档顺序拼成一条**去掉所有空白字符**的字符串，划线记的是这条
字符串上的区间（`text` / `prev` / `next` 三元组），回放时再换回 `(文本节点, 原始区间)`。

**降级顺序不能动**：`prev+core+next` → `prev+core` → `core+next` → `core`。历史数据是按这个
顺序落的，改一处会有一批线换位置。

- 全部找不到时再试**近似匹配**（编辑距离 ≤ 1，长句 ≤ 2；正文 < 6 字符不做）。近似命中用更淡的
  样式画、在列表里标注，**不进未定位清单**——它是成功定位。
- 仍然失败就记 `errCode` 进未定位清单，不丢弃。
- 只靠 `core` 命中且多处出现时，按「前后文重合度」给候选打分取最高（同分取第一处）；
  块编号只在打分时给「跨块的候选」扣分，**不参与偏移计算**。
- 划线的三种状态必须能一眼分清：精确命中 / 近似命中 / 未定位。

**创建与回放的门槛不同，且只留一个长度门槛。** 回放要容忍历史数据，降级到最后一级也照画；
创建侧不需要容忍——一条会被画到别处的线，用户无从发现。所以创建时扩张到上限仍多处命中就
拒绝保存并就地提示。长度下限是 `shared/whitespace.ts` 的 `MIN_TEXT_LEN`，**创建、回放、
提示文案共用这一份**；给回放单独放宽会让这类线存得进去、却既不画出来也不进未定位清单。

## 六、渲染

**只有一种方式：CSS Custom Highlight API**（`CSS.highlights` + `::highlight()`），不给页面加节点。
「包元素」的路子会给页面加节点、破坏框架的 diff、站点重渲染后包裹元素还会丢。

- 注册名按画笔区分，每个名字对应一组 `Range`，一次 `set()` 全部生效。
- **hover 单独一组注册名**，且每次删掉重插以保证它排在最后（压在底色之上）；
  切换 hover 不重注册底色分组。
- 画笔样式来自设置，`::highlight()` 只支持有限属性，映射写在 `shared/styles.ts`。
- 浮层（工具条 / 卡片 / 面板 / 标记点）全在 Shadow DOM，宿主在 light DOM 下**必须零子节点**，
  页面事件靠 retarget 认宿主；识别宿主用**精确标签名**匹配，不能用子串匹配。
- 盒模型 / 尺寸的数值只有一处出处（工具条度量模块），CSS 与坐标计算都从它取，
  不各写一份——两处漂移的表现是浮层错位，且只有肉眼能发现。

性能约束（改渲染层时必须守住）：

| 场景 | 做法 |
| --- | --- |
| 站点 DOM 变动 | 先判「区间两端还在文档、区间文字没变」，是就直接返回，不重建索引也不重定位 |
| 变动频率 | MutationObserver 合并成一次 idle 回调（带超时兜底） |
| 点击 / hover 命中 | 先按光标位置查区间表取候选，**再对候选做像素校验**；不遍历所有矩形 |
| 索引构建 | 祖先过滤与标签黑名单在一次遍历内按元素缓存 |
| 未定位重试 | 只在有失败项、且距上次 ≥ 5s 时，才允许 DOM 变动触发重算 |

像素校验那一步不能省：鼠标停在行尾空白时，浏览器把光标报成「最后一个字符之后」，
只靠字符下标会把划线后面的空白误判成划线本身。

**量性能的口径**：在同一基准页上比「改前 / 改后」的 warm 中位数，不要拿「注入脚本 → 首帧」
当启动成本——首屏布局会被算进渲染耗时里。没有改前那一组数，优化与变慢都看不出来。

## 七、运行结构

### 7.1 上下文分工

| 上下文 | 职责 |
| --- | --- |
| content script | 读划线 → 重定位 → 渲染 → 划词 / 查看 / 删除 / AI 卡片。**直接调 `shared/db.ts`** |
| background | 工具栏图标左键（发消息让页面开面板）与右键菜单、转发 AI 请求、全量同步拉取、角标 |
| 扩展页 | 偏好设置与「我的划线」，共用同一个 HTML 文档 |

不把划线读写经 background 转发，是 4.1 那个决定的直接后果：storage 对 content script 可见。
`storage` 权限同时覆盖 `storage.sync`，所以同步不需要额外权限。

消息面刻意小：content → background 只有「报本页条数」和 AI 相关几种，background → content
只有「开关面板」。

### 7.2 扩展页

构建工具**只为清单里声明的页面角色打包 HTML**，自造的第二个 `.html` 不会进产物。所以
「偏好设置」与「我的划线」共用 `options/index.html`，靠 hash 区分；偏好设置内部再按组分段。
视图标识必须留在 hash 里，否则刷新会掉回默认视图。

切组用 `history.replaceState` 而不是改 `location.hash`：后者会触发 hashchange，
整个视图被卸载重建——正在编辑的提示词会丢焦点、未提交的草稿会回到上次保存的值。

打开扩展页时插到**触发它的那枚标签后面**（同一窗口），不是窗口末尾；源标签读不到就退回默认位置，
不要让打开动作失败。已经打开的扩展页只切过去、不移动。

### 7.3 扩展更新之后

Chrome 不会把已注入的 content script 从打开的标签页里换掉。更新 / 停用 / 卸载后，旧脚本还在
页面里、`CSS.highlights` 与浮层也还在，但 `chrome.*` 全部失效（任何调用都抛
`Extension context invalidated`），也没有 API 能让旧页面换用新扩展。

关键是分清哪些能力真的没了：已画的高亮、hover、命中检测、浮层与标记点的定位**都是纯 DOM/CSS，
照常工作**；失效的只有存储与消息。

所以处理方式是**降级而不是拆除**：不拆 UI、不擦高亮（擦了会让用户以为划线丢了），
只把入口换成「刷新」——划词 / 点划线弹出的工具条只显示一个刷新按钮，点了 `location.reload()`。
要碰 `chrome.*` 的路径统一先判活，失效就跳过，不抛错。

判活用「每秒问一句」的轮询，挂在既有的换页检测定时器上，不额外起定时器。**不用长连接**：
端口断开既可能是扩展没了，也可能是 service worker 正常休眠，那条路要重连 + 心跳，
等于主动把 worker 一直叫醒。

## 八、权限

| 项 | 值 | 为什么 |
| --- | --- | --- |
| `permissions` | `storage`、`contextMenus` | 前者存数据；后者只给工具栏图标的右键加两项入口 |
| `host_permissions` | `https://api.deepseek.com/*` | AI 请求从 service worker 发出，扩展 origin 的 `fetch` 要靠 host 权限才不受 CORS 约束 |
| `minimum_chrome_version` | 130 | `storage.local.getKeys`（4.2 的第二级查找只读键名） |

`content_scripts.matches` 由清单声明，**不额外申请页面访问权限**，也不需要 `scripting`
（不在运行时动态注入）。AI 接口地址不可配，所以没有 `optional_host_permissions`。

加权限要三处同步：清单、本文这张表、`tools/verify-build.mjs` 的期望集。

## 九、划词翻译 / 解释

### 9.1 请求放在 background，用长连接把增量转给页面

三个理由都是硬的：

1. **Key 不进页面上下文**（见 9.5）。
2. **流式要一条长连接**：一次性消息装不下增量，port 可以逐块 `postMessage`。
3. **CORS**：页面源发出的跨域请求永远受 CORS 约束，即使声明了 host 权限；
   只有扩展 origin 的请求能靠 host 权限绕过去。

### 9.2 service worker 与 30 秒

官方的终止条件指 `fetch()` **首字节**超过 30 秒；**读 `response.body` 期间不算活动**。
Chrome 只给 WebSocket 和「通过长连接端口发消息」开了保活，没给 fetch 流开。因此：

- 每收到一个增量就 `postMessage`，这个动作本身就保活；
- 真正危险的窗口只有等首 token。所以**默认关闭思考**（该字段默认开启，首 token 可能十几秒）；
  设置里可以打开，代价是可能撞上 30 秒；
- 客户端再加一层超时，早于服务端上限主动收尾。

**断线不自动重试**：重发会重新生成、重新计费，而服务端没有幂等键、也没有「从半截继续」的语义。
保留已收到的半截正文，给一个显式的重试按钮。

### 9.3 只支持 DeepSeek 官方接口

**地址与模型写死在代码里，设置里没有这两项。** 原因不是偷懒：翻译与解释都用 DeepSeek 的
**服务端联网工具**，换成自建网关、本地模型或别家兼容接口，请求能发出去但联网搜索直接消失。
保留「可填地址」等于给用户留一个「填完看着能跑、悄悄少一半能力」的坑。

与文档对得上、但很容易踩空的事实：

1. **搜不搜由模型判断。** `tool_choice` 指定它直接返 400。所以界面上没有「联网搜索」开关——加了也是假的。
2. **关思考 = 联网搜索；开思考 = 深度思考搜索**（多步、约 20 次调用，更慢）。
3. **引用只在最后一帧下发一次**（`delta.annotations` 里的 `url_citation`），提前发「完成」就会丢。
   所以先攒住来源，流读完再发唯一一条完成。
4. **默认提示词里必须写「先联网核对」的判据。** `tools` 只是「允许使用」，文档不会替你写触发条件；
   不写这句时模型一次也不搜，会把「不确定」当成终点。判据按「有没有不认识的具体对象」分：
   不认识的作品 / 人物 / 机构 / 术语 / 数据 / 事件必须搜、不许猜；常识性的词义、语法与断句
   凭已有知识直接答。太宽的判据会让每个术语都先搜一遍（多花钱、多等首 token），
   太窄的判据会让模型对陌生名字直接写「信息不足」，把一次搜索能确认的事写成免责声明。
   这条由 `prompt.test.ts` 锁住两端。
5. **提示词不得要求模型「给出链接」**：来源是接口自带的，要求它写链接只会让它凭记忆拼 URL。
6. **判断搜没搜只看 `usage` 里的服务端工具次数**（没联网时该字段不存在）。次数挂在用量提示里，
   卡片一行放不下三组数字。

### 9.4 目标语言

`Settings.translateLang` 可以是具体语言或「自动」（默认）。**「自动」不用模型猜**：客户端按书写系统
判方向（中日韩 → 英语，其余 → 简体中文），纯函数、可测、界面能直接显示这次的实际目标。

三条附带规则：

- prompt 里必须是**具体语言名**，写「自动」对模型没有意义。
- 卡片的下拉里**没有「自动」**：打开时就解析成具体语言再选中，用户看到的是真实目标；
  设置页保留「自动」，它是全局默认。
- 卡片上换语言只影响这一次，不写回设置——临时看一句日文不该改掉全局默认。

### 9.5 Key 的存放与威胁模型

磁盘上是密文，明文只在内存里：AES-GCM 加密，包装密钥与密文**分开两个键**、每次安装独立随机生成。
**这两个键一起镜像到 `storage.sync`**（始终，不看 `Settings.syncHighlights`）：Key 是偏好设置的一部分，
换台机器重填一次 Key 是纯摩擦。必须**成对搬运**——只有密文没有包装密钥就是一对死数据。

代价说清楚：包装密钥跟着密文一起上云，所以这层对**跨设备传输**没有保密意义，
它挡的始终是「落盘明文」（见下）。删除用**空值标记**传播——同步区的 `ai:key` 是空串
表示「别的设备删了它」，删键本身分不清「没配过」与「刚被删掉」。

**不讲强度的漂亮话**：包装密钥也在同一份 storage 里，能读你 profile 目录的程序两样都能拿到。
这层实际挡的是「扫磁盘明文」的工具（DLP、备份 / 同步软件、日志、崩溃转储、`grep sk-`）
与误操作（导出 storage、截图、贴进 issue）。挡不住能读 profile 的恶意程序。
不做「用户口令派生密钥」：每次启动都要输口令，与划词工具的使用频率不匹配；真正的保护手段是
用一把专用、限额、可随时吊销的 Key。

三条硬边界：

1. **不进 `Settings`**——`Settings` 会写进备份文件，那文件用户会随手分享出去；而且它走
   `normalizeSettings()` 那一套字段校验，密文塞进去没有意义。Key 单独一对键、单独镜像。
2. **只有两个上下文读明文**：background（发请求）与设置页（掩码展示 / 写入）。
3. **content script 只问一个布尔**。这不只是缩小暴露面：content script 跑在页面 origin 上，
   `http://` 页面不是安全上下文，`crypto.subtle` 在那里是 `undefined`，在页面上解密根本跑不通。

不做旧版迁移：只认当前格式的密文，读到别的值就当「没配」（**不删**——删除会顺着同步链扩散）。

### 9.6 Markdown 渲染

模型输出是**外部输入**。取舍是「解析交给库、渲染留给自己」：库只当 tokenizer 产出 token 树，
渲染用 `createElement` / `textContent` 建 DOM，**一处 `innerHTML` 都没有**。

**绝不能改成 `parse()` + `innerHTML`**：实测它会原样保留 `<img src=x onerror=...>`
（Shadow DOM **不阻止**内联事件），而 DOMPurify 这类清洗库重度依赖 `document`，
在 `node:test` 里跑不了。三条规则覆盖全部风险：

1. `html` token 降级为**纯文本**（不丢弃——丢弃会静默吞内容，显示成字面量既安全又能看出模型写了标签）；
2. 链接白名单只认 http / https / mailto 与相对地址，其余降级成纯文本，连 `<a>` 都不建；
3. 不认识的结构退化成它的原文。宁可丑，不可丢。

图片降级成 alt 文本（卡片里加载远程图片既慢又泄露访问行为）。来源链接同样过白名单——
它是外部输入，直接填 `href` 等于开一个 `javascript:` 后门。

**流式**：每次增量整段重解析。理由不是省时间（实测远低于一次渲染间隔），而是永远拿到完整
上下文——未闭合的标记只有看完整段才知道怎么闭合。

**代价**：`marked` 会进 content script，于是**每个打开的网页**都要解析一份（实测 +100 KB raw、
+13 KB gzip）。要省只能自写只认几种块的解析器，代价是失去表格、引用与嵌套列表。

**不自动滚动**：重渲染与收尾都不写 `scrollTop`，位置全由用户决定。

**复制给原始 Markdown**，不是纯文本：粘进笔记软件时保留标题、列表、代码块与链接。

### 9.7 提示词

每个动作存两条：system（角色、质量标准、边界、联网判据）与 user 模板（这次做什么）。
两者分工固定，**不写同一句话**——写重了不只是浪费 token，改文案时只改得动一处，下一版
就成了两个互相抵消的版本。`prompt.test.ts` 有机械检查（两侧按句读切片段，交集必须为空）。

六条长期约束：

1. **模式与自定义文案是两个字段。** 用「值是否等于默认」判「默认」有一个治不好的毛病：
   内置文案一改，旧值就不再等于新默认，从没自定义过的人也会被认成「自定义」、从此锁在旧文案上。
   分开之后「默认」才真正跟随内置文案升级，切换也不丢东西（切到默认只改模式，自定义文案仍存着）。
2. **占位符是 `{{text}}` / `{{lang}}` / `{{context}}`**，不用 `$` 或方括号：那些字符在正则与代码
   片段里到处都是，误替换的代价是悄悄改了用户的原文。两个位置都生效，可重复出现。
3. **替换值必须用函数形式**（`() => value`）。传字符串时 `$&`、`` $` ``、`$'`、`$$` 会被当成
   替换模式解析，而这里填的是网页正文（常见 `const $$ = …`、正则里的 `$&`）。
4. **拼装层不认识标签。** 模板里那对标签只是默认文案的一部分：不配对、不清理、不校验，
   用户改成别的名字或整段删掉都行。空值就是空串，由此产生的「空标签夹一行空行」是接受的取舍
   ——代码一旦开始配对标签，用户的模板就不自由了。
5. **`{{text}}` 是 user 模板的硬要求**（没有它模型看不到选中的文字）：归一化见不到就整条退回默认，
   设置页则拒绝保存并说明原因，避免用户写的内容被静默丢弃。system 不做这个要求。
6. **不举反例、不写「少说」类限制。** 反例会被模型当成可套用的句式复述，还把默认文案撑长
   （它也会进设置页与 `storage.sync`）。唯一的内容性硬边界是「不要编造」。
   两个容易写反的地方：翻译不能说「不要解释」（不解释的话用户照样看不懂），
   解释不能说「不要重复原文」（解释常需引几个词锚定自己在讲哪一处）。

默认模板是**三段、段间一个空行**（上下文块 / 任务 / 原文块）。空行是段分隔不是排版：
没有它，上下文与任务句会粘成一段。用 XML 风格命名标签而不是引号围栏，是因为上下文块
**本来就含选中原文**，同名围栏会让「下面这一段」指哪一段只能靠位置推断。

归一化只有三条：换行统一成 `\n`、长度封顶、非法值退回默认。

### 9.8 不引 SDK

`openai` 一个入口就 88 KB gzip 且要求浏览器逃生舱，`ai` 更高。本场景只有「单轮文本流式」
一条路径，`fetch` + 自写 SSE 解析（零依赖、`node:test` 可直接跑）足够。SSE 解析里的几个坑
（裸 `\r`、空 `data:`、注释行、超限恢复）都由单测锁住。
